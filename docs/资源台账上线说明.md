# 资源台账上线说明

本功能为现有 AI 教研助手新增资源后台。它不改动既有 `teachers`、`courses`、`teacher_courses` 表；启用前仍按原流程配课。

## 上线前准备

1. 在 CloudBase PostgreSQL 的 SQL 控制台执行 `migrations/001_resource_ledger.sql`。脚本只新建 `wb_imports`、`wb_identity_links`、`wb_login_guard` 及登录限流函数。
2. 确认当前 `CLOUDBASE_API_KEY` 所对应的数据库角色具有新表的 `SELECT`、`INSERT`、`UPDATE` 权限，以及 `wb_allow_login()` 的执行权限。脚本默认授予 `service_role`；如果实际角色名称不同，仅为该服务端角色授予相同权限，不能开放给 `anon` 或 `authenticated`。
3. 在 EdgeOne Pages 的 Edge Functions Secrets 中配置下列变量。密码和密钥使用 Secret 类型，勿提交到 GitHub。

| 变量 | 用途 | 要求 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 资源管理员登录口令 | 至少 16 个字符 |
| `WORKBENCH_PASSWORD` | 仅可进入前台配课的业务口令 | 至少 16 个字符，可与管理员不同 |
| `ADMIN_SESSION_SECRET` | 签发 8 小时安全会话 | 随机值，至少 32 个字符 |
| `RESOURCE_LEDGER_ENABLED` | 资源后台与前台联动开关 | 先设为 `false`，验收通过后改为 `true` |
| `CLOUDBASE_ENV_ID`、`CLOUDBASE_API_KEY` | 原有数据库连接 | 继续使用服务端密钥 |
| `DEEPSEEK_API_KEY`、`BOCHA_API_KEY` | 原有方案生成与联网检索 | 继续使用服务端密钥 |

EdgeOne 将 Secret 作为 Edge Function 的运行时变量提供；变量保存后须重新部署函数才会生效。[EdgeOne 环境变量说明](https://edgeone.ai/document/62764)

## 推荐上线顺序

1. 合并并部署本次代码，保持 `RESOURCE_LEDGER_ENABLED=false`。既有前台继续按原方式工作。
2. 执行数据库迁移，设置登录变量，访问 `/admin.html` 登录并上传三份样表。
3. 检查每批识别数量、提示信息和来源，再点击“发布”。发布后仍保持开关为 `false`，先核查台账记录。
4. 改为 `RESOURCE_LEDGER_ENABLED=true` 并重新部署。此后前台须先在资源后台登录；新方案从已发布的台账动态匹配。
5. 用一个真实培训需求验收：库内课程应显示“库内师资”，中介记录应显示“中介师资”，无匹配课程应保持“待匹配”并给出“网络检索”候选（已配置检索密钥时）。

## 师资来源规则

| 来源 | 录入方式 | 前台显示 |
| --- | --- | --- |
| 库内师资 | 课程表、师资表；“师资来源”列填写或默认识别为此值 | 库内师资 |
| 中介师资 | 中介师资表，或“师资来源”列填写 `中介师资` | 中介师资 |
| 网络检索 | 课程缺口触发市场检索；需有搜索结果中的人名与来源链接 | 网络检索 |

“网络检索”只表示线索渠道，页面会同时展示来源链接和待核验说明。它不自动进入已发布台账。

## 首次验收清单

- 三份样表分别显示为 20、19、5 条原始记录；其中师资表的多门“讲授课程”会在配课时拆为多个候选。
- 重复上传同一文件只返回已有批次；重复出现不提高推荐权重。
- 同名老师无法确认时显示提示和可选身份，不显示未确认的单位或简介。
- 撤回批次后，新方案不再使用该批次；历史方案保持原快照。
- 未登录、业务口令用户不能上传、发布或撤回资料。
