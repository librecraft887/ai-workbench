# AI教研助手 V1.3｜需求澄清、客户调研与配课方案

本版按实际培训项目的业务顺序运行：互动提问明确需求 → 调研与本次培训有关的客户背景 → 综合分析并设计配课。调研结果参与课程选择和安排，页面、复制文本、Word 共用“项目背景”“客户需求分析”“方案设计逻辑”三段正文。

## 工作流程

1. 在新项目中填写客户名称，并在对话框录入培训需求。
2. 客户名称、培训对象、培训主题、天数、培养目标/希望解决的问题缺失时，用互动提问补充；已明确的信息保留，不重复追问。用户可明确选择“暂不提供客户”或“请建议培养目标”。
3. 业务问题、学员基础、师资偏好和教学组织要求一并吸收；未说明时不猜测。课次缺失按每天上午、下午各一讲安排，并在方案概览注明。
4. 需求完整后才调研。主检索围绕培训主题检索客户战略、业务和人才培养；主链路失败时，博查的四组问题同样带入培训主题和对象。
5. 调研完成后，才加载师资课程数据并生成三段分析及配课。资料不足时只依据已确认需求设计，页面说明资料情况。
6. “重新调研并更新方案”重新执行调研与设计，更新正文及课表。需求、客户或培养目标变化时，旧调研缓存失效。

## 客户调研输出

每次调研围绕以下维度：

- 客户画像：机构性质、业务范围；
- 战略与业务：中长期战略、年度重点、近期业务信号；
- 人才与能力：干部培养、培训体系、数字化及岗位能力线索；
- 培训设计启示：必须对应至少一个来源编号，不代表客户已经提出未被公开资料证明的内部需求；
- 公开资料来源：标题、证据、URL、发布日期（如有）。

主检索的 URL 必须有联网响应中的引用支撑；没有可验证引用时，主检索不会保留模型写出的 URL。备用博查结果直接保留供应商返回的 URL。所有链路均不向前端显示供应商错误、Key、HTTP 响应或堆栈。

## 页面、Word 与项目隔离

- 正文先展示三段连贯分析：项目背景（为什么开展）、客户需求分析（提升什么能力）、方案设计逻辑（为何采用这些模块、顺序和教学方式），自然过渡到配课方案。
- 每行课程说明回应的需求、预期能力和教学阶段；事实对应来源编号。
- 原始检索摘要保留在页面末尾的“公开资料参考”展开项中，Word 与复制文本仅保留参考来源附录，不堆叠原始摘要。
- 同一项目的培训需求发生实质变化时，系统会按新需求重新调研，不复用旧的课程设计启示。
- 异步请求会绑定发起项目；用户切换项目后，旧请求不会污染新项目。
- Word 和“复制文本”共用同一方案章节，顺序为：项目背景、客户需求分析、方案设计逻辑、培训安排概览、配课方案、推荐师资简介、备选师资（待确认）、公开资料参考。Word 参考来源为可点击链接。
- 主检索事实后引用[S1]等编号；备用检索摘要仅作为公开检索线索，未经原文核验不直接写为官方战略结论。
- 旧项目没有三段正文时，应先补充培养目标并更新方案，再复制或导出 Word。
- 正式课表仍只使用库内、状态有效且教师课程关系已确认的数据；外部候选只作补充，不能进入正式课表。

## 本地验证

```powershell
node --test tests/*.test.mjs
node --check edge-functions/api/chat.js
node --check edge-functions/lib/research/service.js
```

验收覆盖：缺失目标先提问、先调研后设计的真实接口流程、需求变化后重做调研、调研失败继续按需求设计、无效来源编号过滤、备用问题带入培训需求、页面与复制正文顺序、实际 Word 压缩包中的章节与来源链接，以及博查响应和师资简介边界。
